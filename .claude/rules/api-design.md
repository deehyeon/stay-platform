# API 설계 가이드

## 통합 검색 API

### 엔드포인트 최소 계약

```
GET /api/v1/stays/search?checkIn={date}&checkOut={date}&adults={n}&children={n}
```

검색 조건은 **날짜와 인원뿐**이다. 지역·키워드 필터는 제공하지 않으며, 조회 대상은 보유 숙소 전체다.

### 응답 필수 포함 필드

| 필드 | 설명 |
|------|------|
| 내부 숙소 식별자 · 숙소명 | 공급사 코드가 아닌 자사 식별자 |
| 내부 객실 타입 식별자 · 객실 타입명 | 동일 |
| 최대 수용 인원 | 객실 1실 기준 |
| 예약 가능 객실 수 | 요청 기간 전체를 예약할 수 있는 수. `0`이면 예약 불가 |
| 출처 공급사 | 어느 공급사에서 온 상품인지 |
| 요금 | 구성은 자유롭게 설계 |
| 부분 실패 사실 | 일부 공급사 조회가 실패한 경우 응답에 드러나야 함 (표현 방식 자유) |

### 연박 재고 판정

N박 예약 가능 객실 수 = 해당 기간 **모든 날짜의 `remainingRooms` 중 최솟값**

```
예) 9/1: 3개, 9/2: 0개, 9/3: 5개 → 예약 가능 객실 수 = 0 (예약 불가)
```

### 대량 숙소 처리

공급사 재고·요금 API는 한 번에 **최대 50개** 숙소 코드를 받는다.  
보유 숙소가 50개를 초과하면 청크 단위로 나눠 병렬 호출한 뒤 결과를 합친다.  
청크 분할 및 병렬 처리 전략을 설계 문서에 명시한다.
